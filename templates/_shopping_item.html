{# Phase 3E: swipe-to-delete wrapper. The outer div keeps its stable id so backward-compat tests (which locate items by `id="shopping-item-N"`) still work. Underneath it we render two stacked layers: 1. A red "Delete" affordance layer (absolute, aria-hidden) that sits BEHIND the content. It's fully opaque all the time — the reveal is done purely by the content sliding to the left, so no opacity animation is needed. 2. A `data-swipe-content` layer that holds the actual row UI (checkbox / name / actions). This is the element the swipe JS translates. It carries `data-delete-url` so the JS can fire the DELETE request without needing to introspect buttons. The visible Delete button INSIDE `data-swipe-content` stays present — swipe is an accelerator, not a replacement. That preserves keyboard/screen-reader access and gives new users a discoverable path. #}

{# Phase 6E (bug fix, plan §0.1): the checked-off dim used to be `opacity-60` on THIS wrapper. Bad: opacity applies to the entire stacking context including `bg-white`, so the red affordance layer above bled through at 40% and checked rows rendered as pink blocks with "Delete" visible behind them. Moved to `[&>*]:opacity-60` so ONLY the direct children (checkbox label, content column, actions column) dim — the row's white background stays 100% opaque and fully occludes the affordance at rest. Same visual "dim" effect for the user, no red-leak. #}
